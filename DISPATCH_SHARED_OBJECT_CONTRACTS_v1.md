# 0. Why This Document Exists

Build Command Section 5 requires shared interface contracts to be defined **before** department
internals are coded, because Intelligence, Library, and Publisher are one dependency chain, not
three independent projects. This document is the single canonical schema source. Each department
repo (Intell / Library / Publisher) implements these exact field names in its own `models.py` /
schema file so objects passing between repos are structurally compatible without a shared package
dependency (per 07_DISPATCH_REPO_PLACEMENT_PLAN.md, each repo is independently buildable —
compatibility is achieved by contract discipline, not by code sharing).

Every object below answers the Matrix Compliance Test (System Relationship Matrix Section 12):
what is created, who owns it, where it is stored, temporary/current-truth/history, who may
consume it, who may not, review requirement, approval requirement, Library-candidate status,
Archive requirement, Portal/Work Item creation, governing test, forbidden path, cognitive-load
effect.

# 2. Conventions Used By Every Object

- `id` fields are opaque strings (UUID4 recommended), generated by the owning service, never by
  the caller.
- `created_at` is an ISO-8601 UTC string, stamped by the owning service.
- Every object that can become "truth" carries an explicit boolean or status field proving it is
  not truth by default — there is no implicit-approval state anywhere in this contract set.
- No object schema below includes a field for an outbound customer, broker, or government contact
  address/channel. That is intentional: no such field can appear later without a contract change
  reviewed against the Forbidden Actions in the Constitution.
- "Approval requirement: external" means the code path enforces that the approving identity is not
  the same identity as the system/service that produced the object (Publisher cannot self-approve;
  Intelligence findings cannot self-promote).

# 6. Required Service Surfaces (per department, matching System Relationship Matrix §8)

```
intell.create_finding(...)              -> IntelligenceFinding
intell.route_to_publisher(finding)       -> PublisherRequirement[]
intell.route_to_library(finding)         -> LibraryCandidate
intell.create_decision_support_note(...) -> ManagerDecisionSupportNote

library.current(object_code)             -> LibraryObject | None
library.resolve_packet(recipe_type)      -> {object_code: LibraryObject}
library.submit_candidate(candidate)      -> LibraryCandidate (status PENDING_REVIEW)
library.review_candidate(id, approve, reviewed_by) -> LibraryCandidate | LibraryObject
library.ingest_human_document(...)       -> LibraryObject (status CURRENT, source HUMAN_PLACED)

publisher.create_request(...)            -> PublisherRequest
publisher.create_readiness_packet(req)   -> ReadinessPacket
publisher.pull_libraries(req)            -> Workspace (via Library service contract)
publisher.create_inventory(req)          -> PartsInventory
publisher.create_missing_notice(req)     -> MissingItemNotice
publisher.create_review_package(req)     -> DraftReviewPackage (status DRAFT)
publisher.approve_review_package(id, approver_id) -> DraftReviewPackage (status APPROVED_BY_MIKE)
publisher.create_archive_handoff(review_id) -> ArchiveHandoffPackage
publisher.create_visibility_package(req) -> VisibilityPackage
publisher.create_pod_bundle(req)         -> PODEvidenceBundle
```

Each department repo implements its own side of this table. Cross-repo calls (e.g. Publisher
calling `library.current()`) are modeled as a `LibraryClient` interface inside the Publisher repo
that a real integration would point at the Library service; for integration-ready local testing
each repo ships an in-process reference implementation plus a documented interface boundary.

# 7. Hard Rule Enforcement Map

| Hard Rule | Enforced By |
|---|---|
| Publisher may not approve itself | `approve_review_package` requires external `approver_id`; test asserts self-id rejected |
| Publisher may not submit externally | No network/email/API-send code exists anywhere in Publisher repo; grep-based test asserts this |
| Intelligence findings not automatically truth | `is_final_decision`/`library_truth` fixed False on Finding; only approved Library Candidates become truth |
| Archive is not current truth | No Archive→Library code path in any repo; handoff is one-directional |
| Human-placed Library documents accepted per doctrine | `ingest_human_document` creates CURRENT status directly, no review-loop dependency |
| No autonomous customer/broker/government communication | No such fields/methods exist in any schema in this document |
| No authority bypass | Every approval-gated transition requires an external identity argument, tested |
| Mike remains final authority | No object in this contract set has a code path to become truth/approved/sent without an external `*_by`/`approver_id` argument |
