## 1. Purpose

This matrix evaluates every major architecture area defined by Claude-3 governance (culminating in `DISPATCH_FINAL_BLUEPRINT_v1.md`) against what actually exists today in the `jax1313-outlook/Dispatch` implementation repository (`cin_lite/`, `dispatch/`, `portal/`, `sync/`, `tests/`, deployment docs, CI, and the phase-by-phase `DECISION_LOG.md` / walkthrough-report history).

Reuse before rebuild. Modify before replace. Archive before delete. Reject only when an existing asset violates final doctrine or cannot be safely adapted. No item here authorizes a code change by itself — every Decision is a recommendation for Mike's review, feeding the Migration Plan and Jules Build Matrix in `DISPATCH_INTEGRATED_BLUEPRINT_v1.md`.

**Current Fit** values: Strong Match · Partial Match · Weak Match · Conflict · Missing · Unknown
**Decision** values: Keep · Modify · Integrate · Promote · Archive · Reject · Build New · Investigate Further
**Priority** values: Critical · High · Medium · Low · Future

## 3. Cross-Cutting Observations

- **The single most valuable existing asset** is the combination of `cin_lite/archive.py`'s fail-closed SHA-256 integrity mechanism and `dispatch/services.py`'s `IFTAReportApproval` draft→sealed gate — together they are the closest thing in the codebase to a working Spine fragment (Archive integrity + Approval Event), and both should be preserved and generalized rather than rebuilt.
- **The single most urgent gap** is Security and Authentication (rows 13, 23, 29–31): there is no authentication, authorization, role, or PIN mechanism anywhere in the running application, confirmed by direct code inspection and grep sweep. `DEPLOY_VPS.md` already names this as a blocker in its own words.
- **Doctrine correction (supersedes the original row 8 finding):** `LIBRARY_INGESTION_RULE.md` confirms that immediate, ungated acceptance is the *correct* behavior for human-placed Library documents — `portal/models/library.py`'s existing auto-approve-on-creation behavior was not actually a conflict for that path. The remaining gap is narrower: the code has no `origin` field distinguishing a human-placed document from a Publisher-generated one, so a future Publisher integration could accidentally reuse the same ungated path Publisher output must never use. This is now a Modify, not a Conflict, and drops from Critical to High priority.
- Old **"L2-COS"** terminology appears in `README.md`'s section header ("L2-COS Operations Portal v1"). Per `SUPERSESSION_MAP.md`, legacy terminology does not control current architecture; this is a low-risk naming cleanup item, not a doctrine violation, and should be renamed opportunistically rather than urgently.
- The Dispatch repo's own `dispatch/` Python package name (the trucking/load-board domain) and the platform name "Dispatch" are already overloaded in the existing codebase. This predates this reconciliation and is not something to rename destructively — it is noted here so the Integrated Blueprint's repository structure recommendation accounts for it rather than compounding it.
